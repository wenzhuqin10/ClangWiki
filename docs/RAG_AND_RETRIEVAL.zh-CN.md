# 混合检索与 RAG 引用规范

## 1. 索引来源与切块

索引包含当前生成快照、集合 Wiki、人工知识页、批注、模块描述、函数/类型/宏源码块、CMake 配置和已确认关系。文档按 Markdown 标题切块；代码按函数、结构体、枚举和宏组切块。块 ID 是内容与来源构成的稳定哈希，并保存仓库、模块、文件、符号、提交和证据等级。

代码块会附带结构化描述，例如：

```text
Symbol: pdsch_encode
Module: phy/pdsch/encoder
Calls: crc_attach, ldpc_segment, ldpc_encode
Defined at: src/phy/pdsch/encoder/pdsch_encode.c:42
Source: ...
```

已确认的调用、读写、类型、回调、接口、配置和领域关系会生成独立的 `graph` 证据块。图谱块进入 FTS5 和关系扩展，但不逐边执行 Embedding；候选与已拒绝关系默认不进入仓库索引，避免把 `POSSIBLE_CALL` 当作确定事实，也避免大仓库为数万条短边重复消耗 CPU 和内存。

## 2. 四路召回与融合

1. **符号检索**：函数、类型、宏、字段、路径的精确匹配。
2. **全文检索**：SQLite FTS5 召回中文、英文、标题和标识符。
3. **向量检索**：默认 BGE-M3 ONNX + USearch 持久化索引。
4. **图关系扩展**：调用者、被调用者、父子模块和跨仓接口。

四路结果经 Reciprocal Rank Fusion 融合，并对精确符号、当前范围、编译器确认关系、模块邻近度、标题命中、当前快照和人工确认关系进行确定性加分。向量运行时不可用时，会明确提示并自动退化为符号、全文和图谱检索。

默认向量档：`BAAI/bge-m3`（1024 维、ONNX CPU 推理）；兼容档为 `intfloat/multilingual-e5-small`（384 维）与 `intfloat/multilingual-e5-large`（1024 维）。模型缓存仅能由离线准备步骤或管理员显式放入 `models/`，运行时不隐式下载。

## 3. RAG 执行链

```text
问题
→ 选择仓库/知识空间
→ 混合检索与关系扩展
→ RRF 融合 + 上下文预算
→ 生成带固定证据 ID 的 context.md
→ opencode run
→ GLM-5.1 回答
→ 引用校验与一次修复
→ 保存会话、回答和引用
```

短会话最多携带最近四轮摘要；每轮均重新检索，不把长会话原文无限追加到模型上下文。

## 4. 引用契约

| 前缀 | 证据 | 示例 |
|---|---|---|
| `W` | 仓库或集合 Wiki | `[W1]` |
| `C` | 源码及行号 | `[C2]` |
| `G` | 代码关系图 | `[G3]` |
| `M` | 人工知识页或批注 | `[M4]` |

模型只能引用本轮上下文中分配的 ID。回答完成后，系统校验：引用是否存在、来源 URI 是否可打开、候选关系是否被误称为确定调用。出现无效引用时，会基于同一批证据发起一次修复；仍不合格时，返回“回答校验失败”，不显示未经校验的模型文本。

`[G]` 引用包含关系类型、状态、来源提取器、置信度和源码位置。默认图扩展 SQL 只读取 `status=confirmed`；社区成员关系只用于扩大召回范围，不作为调用或数据流证据。

无足够证据时，模型必须写明“根据当前可访问的代码和文档无法确定”，并说明所需的源文件、调用方、日志、配置、测试或提交历史。
